# Global preferences

## Writing language

Always write **code and documentation in English**, in every project, whatever
language we are speaking in:

- identifiers, function and variable names
- code comments
- README files, docs, design notes
- commit messages and PR descriptions

Conversation follows the user's lead: if they write in French, answer in French.
Only the artefacts committed to a repository are English.

## Typography: never use the em dash

**Never write an em dash (`—`, U+2014), in any language, anywhere.** Not in
prose, not in code, not in comments, docs, commit messages, PR descriptions,
markdown content, or chat replies. It has become the single most recognizable
tell of AI-generated text, so it must not appear in anything written here.

Rewrite instead of substituting a look-alike:

- appositive or aside → comma (`the studio, the company behind Bref`)
- introducing a list or an explanation → colon (`every technical choice:
  WordPress, one Lazy Block per production`)
- parenthetical interruption → parentheses (`upgrades (several over the
  mission) stopped hurting`)
- two independent clauses → semicolon or two sentences

The en dash (`–`) stays legitimate for numeric ranges (`2012–2015`). Hyphens in
compounds are unaffected. When editing existing text, remove any em dash you
find in the lines you touch.
